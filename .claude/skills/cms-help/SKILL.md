# 記事入稿のヘルプ

指定されたコマンド: `$ARGUMENTS`（空の場合は一覧を表示）

編集担当者向けに、使えるコマンドと使い方を説明する Skill です。説明の内容は
[references/commands.md](references/commands.md) にまとめてあります。最初にこのファイルを読み、その内容に沿って答えてください。

## 守ること

- **表示するだけにする。** コマンドの実行、ファイルの作成・変更、Git・GitHub・Docker の操作は一切しない。
  使えるツールは Read（説明ファイルを読む）だけ。説明を読んだ利用者から作業を頼まれたら、そこで初めて該当するコマンドの手順に移る。
- 専門用語は避け、使う場合は「ことば」の表の説明を添える。説明ファイルにないことを推測で付け足さない。
- Claude Code 自体の使い方（`/help` など）を聞かれた場合は、Claude Code の標準のヘルプを案内する。

## 答え方

### コマンドの指定がないとき（「何ができるの？」など）

説明ファイルの「一覧」の表をそのまま示し、続けて次を添える。

- 話しかけるだけでも同じことができること
- 詳しく知りたいときは `/cms-help publish-news` のようにコマンド名を付けること
- はじめての場合は `/setup-editor` から始めること

### コマンドが指定されたとき

1. 指定を次のように読み替える。
   - 先頭の `/` はあってもなくてもよい（`publish-news` と `/publish-news` は同じ）。大文字・小文字は区別しない。
   - 日本語での指定は内容で対応させる（例: 「公開」→ `/publish-news`、「修正」「直す」→ `/edit-news`、「入稿」「新規」→ `/draft-news`、
     「プレビュー」→ `/preview`、「セットアップ」「準備」→ `/setup-editor`）。
2. 説明ファイルの該当する節を、見出し（何ができるか・いつ使うか・必要な情報・実行例・処理の流れ・注意事項）の順に示す。
3. 文中に「ことば」の表にある用語が出てきたら、必要に応じて意味を一言添える。

### 一覧にないコマンドが指定されたとき

- 「`<指定されたもの>` というコマンドはありません」と伝える。
- 名前が似ているコマンドがあれば「もしかして `/draft-news` ですか？」のように 1 つ提案する。
- 続けて「一覧」の表を示す。`/help` など Claude Code 自体のコマンドだった場合は、標準のヘルプであることを伝える。

### 質問の形で聞かれたとき（「記事を公開するには？」「マージとデプロイの違いは？」など）

該当するコマンドの節や「ことば」の表を使って、質問に直接答える。長くなる場合は要点だけを示し、
詳しくは `/cms-help <コマンド名>` で見られることを添える。
