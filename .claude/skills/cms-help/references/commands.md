# 記事入稿コマンドの説明（/cms-help が表示する内容）

> 各コマンドの実際の動きは `.claude/skills/<コマンド名>/SKILL.md` に書かれています。
> そちらを変更したら、このファイルも合わせて更新してください（`npm run test:scripts` で食い違いを確認できます）。

## 一覧

| コマンド | できること |
| --- | --- |
| `/setup-editor` | 記事を書く準備ができているか確認し、プレビューを使えるようにする |
| `/preview [slug]` | 手元のパソコンで記事の見た目（プレビュー）を開く |
| `/draft-news` | 原稿と画像から新しい記事（日本語・英語）を作り、確認依頼（PR）を出す |
| `/edit-news [slug]` | すでにある記事の一部を直し、確認依頼（PR）を更新する |
| `/publish-news` | 確認が終わった記事を、承認をもらってから公開する |

コマンドを入力しなくても、「新しいお知らせを入稿したい」「プレビューを見せて」のように話しかければ同じことができます。

公開中の Web サイト: https://erj-haru.github.io/est-rouge-cms-demo/

## ことば

| ことば | 意味 |
| --- | --- |
| slug（スラッグ） | 記事の URL に使う英語の名前。例: `site-renewal` → `http://localhost:4321/ja/news/site-renewal/` |
| プレビュー | 自分のパソコンだけで見られる、記事の確認用の表示（http://localhost:4321） |
| 下書き | まだ公開しない状態の記事。プレビューでは「下書き」の印付きで表示される |
| PR（プルリクエスト） | GitHub 上の「この変更を確認してください」という依頼。記事の作成・修正は必ず PR を通して行う |
| マージ | PR の内容を、公開用の記事データ（main）に取り込むこと |
| デプロイ | 記事データを実際の Web サイトに反映すること。マージとは別の作業で、マージの数分後に自動で行われる |

## /setup-editor

**何ができるか**
記事を書くのに必要なもの（Git・GitHub・Docker など）がそろっているかを確認し、足りないものがあれば準備の手順を日本語で案内します。準備ができていれば、プレビューを使える状態にします。

**いつ使うか**
- はじめて使うとき
- 「プレビューが開かない」「GitHub につながらない」など、調子が悪いとき

**必要な情報**
ありません。事前に Docker Desktop を起動しておいてください。

**実行例**
- `/setup-editor`
- `/setup-editor --check`（確認だけして、プレビューは起動しない）
- 「このプロジェクトの記事入稿環境をセットアップして」

**処理の流れ**
1. 必要なソフトと GitHub へのログイン、リポジトリへの参加状況を確認する
2. 足りないものがあれば、何をすればよいかを順番に案内する
3. そろっていればプレビューを起動し、表示できることを確かめる
4. プレビューの URL を表示する

**注意事項**
- GitHub へのログインは、案内に従ってご自身のターミナルで行います。パスワードや認証コードを Claude Code に貼り付けないでください。
- 何度実行しても大丈夫です。すでに動いているプレビューを止めたり、やり直したりはしません。

## /preview [slug]

**何ができるか**
手元のパソコンでプレビューを開きます。止まっていれば起動し、NEWS 一覧の URL を表示します。記事の slug を付けると、その記事の日本語・英語ページの URL も表示します。

**いつ使うか**
- 書いた記事や直した記事の見た目を確認したいとき
- 2 回目以降、作業を始めるとき

**必要な情報**
見たい記事がある場合は、その記事の slug（分からなければ記事のタイトルでも探せます）。

**実行例**
- `/preview`
- `/preview site-renewal`
- 「さっき書いた記事をプレビューで見たい」

**処理の流れ**
1. プレビューが動いているか確認する（止まっていれば起動する）
2. 記事が指定されていれば、その記事のページを探す
3. NEWS 一覧と記事ページの URL を表示する

**注意事項**
- 下書きの記事もプレビューでは表示されます（「下書き」の印付き）。
- すでに動いているプレビューは再起動しません。
- プレビューは自分のパソコンでだけ見られます。ほかの人には見えません（公開中の Web サイトとは別のものです）。

## /draft-news

**何ができるか**
原稿と画像から、新しい NEWS 記事を日本語版・英語版の両方で作ります。内容を確認したうえで、GitHub に確認依頼（PR）を出し、PR とプレビューの URL をお知らせします。

**いつ使うか**
新しいお知らせ・プレスリリース・イベント・採用情報を載せたいとき。

**必要な情報**
- 原稿（文章を貼り付けるか、ファイルを渡す）
- 画像（ファイルをターミナルにドラッグ＆ドロップすると場所を渡せます）
- 公開日、カテゴリー（お知らせ / プレスリリース / イベント / 採用）
- サムネイルにする画像
- 足りない情報は Claude Code が質問します

**実行例**
- `/draft-news`
- 「この原稿と画像でお知らせを入稿して」

**処理の流れ**
1. 足りない情報を質問し、記事の slug を提案する
2. 同じ slug の記事がないか確認し、作業用のブランチを用意する
3. 画像を Web 用に整える（大きさの調整、撮影場所などの情報の削除）
4. 日本語版と英語版（翻訳案）の記事を作る
5. 記事のチェックとプレビュー表示の確認をする
6. 送信先とファイルを示し、了承をもらってから GitHub に確認依頼（PR）を出す
7. PR とプレビューの URL を知らせる

**注意事項**
- 新しい記事は **下書き** として作られます。この時点では公開されません。公開は `/publish-news` で行います。
- 英語版は Claude Code による翻訳案です。人名・役職・製品名などは確認を求められます。
- 原稿にない日付や数字などを Claude Code が勝手に補うことはありません。
- iPhone の写真（HEIC 形式）は使えないため、JPEG で書き出してから渡してください。

## /edit-news [slug]

**何ができるか**
すでにある記事の、頼んだ部分だけを直します。確認依頼（PR）が進行中ならその PR を更新し、なければ新しい PR を出します。修正後のプレビュー URL をお知らせします。

**いつ使うか**
- 入稿した記事の日付・文章・画像を直したいとき
- 公開済みの記事を修正したいとき

**必要な情報**
- 直したい記事（slug、またはタイトル）
- 直したい内容（例:「業務開始日を 11 月 24 日にする」）

**実行例**
- `/edit-news site-renewal`
- 「new-office-opening の公開日を 11/21 に直して」

**処理の流れ**
1. 対象の記事と、進行中の PR があるかを確認する
2. 直す範囲を確認する（日本語版・英語版の両方に関わる場合は、もう一方の直し方も確認する）
3. 該当する箇所だけを書き換え、チェックとプレビュー表示の確認をする
4. 変更点を示し、了承をもらってから PR を更新する（または新しく出す）
5. PR とプレビューの URL を知らせる

**注意事項**
- 公開済みの記事も、必ず PR を通して直します。直接は書き換えません。
- slug を変えると記事の URL が変わるため、原則として変えません。
- 差し替え前の古い画像ファイルは削除しません。

## /publish-news

**何ができるか**
確認が終わった記事を公開します。記事の下書き状態を解除し、自動チェックが通ったことを確かめてから、PR をマージします。条件がそろわなければ、理由を説明して止まります。

**いつ使うか**
プレビューで内容を確認し、公開してよいと判断したとき。

**必要な情報**
公開する記事の PR 番号、または slug。

**実行例**
- `/publish-news 2`
- `/publish-news new-office-opening`
- 「確認したので公開して」

**処理の流れ**
1. 公開する記事を特定し、タイトル・プレビュー URL・確認対象の版を表示する
2. **あなたから明確な公開の指示をもらう**
3. 公開してよい条件がそろっているか、事前に確かめる（まだ何も変えません）
4. 記事の下書き状態を解除し、自動チェックがもう一度通るのを待つ
5. マージの直前に、すべての条件をもう一度確かめる
6. PR をマージし、承認の記録を残す
7. Web サイトへの反映（デプロイ）が終わるのを確認する
8. マージとデプロイの結果を分けて知らせる

**注意事項**
- **明確な承認が必要です。** 記事とプレビューを見せた後に、「公開してください」のようにはっきり指示してください。最初に「確認したので公開して」と頼んでいても、あらためて確認します。「たぶん大丈夫」のようなあいまいな返事では公開しません。
- **確認した後に記事が変わっていた場合は公開しません。** もう一度プレビューで確認してから指示してください。
- **マージとデプロイは別のことです。** このコマンドが行うのは「マージ（公開用の記事データへの取り込み）」までです。実際の Web サイト（https://erj-haru.github.io/est-rouge-cms-demo/）に表示されるのは、その後に自動で行われる「デプロイ（サイトへの反映）」が成功したときです。通常はマージの数分後に反映されます。Claude Code が反映まで確認し、マージとデプロイの結果を分けてお知らせします。
- デプロイが失敗した場合、記事は取り込まれていますが、Web サイトには表示されません。お知らせされた URL を担当者に伝えてください。
- 1 回の承認で公開できる記事は 1 つです。記事以外の変更（プログラムなど）を含む PR は公開できません。
- 自動チェックが失敗した場合は公開されません。同じ指示をもう一度出すと、途中から再開できます。
