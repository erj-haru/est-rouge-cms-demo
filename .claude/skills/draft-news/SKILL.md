# NEWS 記事の新規入稿

編集者から受け取った情報: $ARGUMENTS

記事の作成と GitHub への入稿 PR 作成までを行う Skill です。Git・GitHub・検証・プレビューの処理はすべて
`scripts/news.mjs` が行います（`/preview` と同じプレビュー環境を使用）。git や gh のコマンドを直接組み立てないでください。
記事の書き方は [references/article-format.md](references/article-format.md) に従います。最初に必ず読んでください。

やり取りは日本語で、編集者がエンジニアでない前提で進めます。GitHub の画面操作は求めません。

## 手順

### 1. 原稿と情報を受け取る

- 原稿（本文・ファイル）、画像、公開日などを受け取る。画像はファイルのパスで受け取る
  （ターミナルにファイルをドラッグ＆ドロップするとパスを入力できる、と案内する）。
- 次の項目がそろっているか確認し、**不足分はまとめて 1 回で質問する**。推測で埋めない。
  - 公開日 / カテゴリー（お知らせ・プレスリリース・イベント・採用）/ 日本語タイトル
  - サムネイルにする画像と、各画像の代替テキスト（候補を提案して確認）
  - 英語版を作るか（既定: 作る）
  - 公開状態（既定: 下書き `draft: true`。マージしても公開されない）
- slug を英語タイトルから提案し、編集者の了承を得る。

### 2. 重複確認とブランチ作成

1. `node scripts/news.mjs check --slug <slug> --article-id <slug>` — 重複があれば別の slug を提案する。
2. `node scripts/news.mjs start --slug <slug>` — 入稿用ブランチ `content/news-<slug>` を用意する。
   未コミットの変更があって止まった場合は、出力されたファイルを編集者に示して指示を仰ぐ（勝手にコミット・破棄しない）。

### 3. 画像の配置

`node scripts/news.mjs images --slug <slug> <画像1> <画像2> ...`（サムネイルにする画像を先頭にする）

- 長辺 2400px への縮小、向きの補正、位置情報などのメタデータ削除が行われ、`src/assets/news/<slug>/` に配置される。
- 出力された「記事からの参照パス」を記事で使う。HEIC などで失敗した場合は、JPEG で書き出してもらうよう案内する。
- 既存の画像を上書きする `--overwrite` は、編集者の明示的な了承がある場合のみ使う。

### 4. 記事ファイルの作成

- 日本語版: 原稿の文章を尊重し、構成（見出し・箇条書き・表）を整える程度にとどめる。事実を追加・変更しない。
- 英語版: 翻訳案として作成する。訳に迷う固有名詞・役職などは候補を示して確認する。
- 既存ファイルを上書きしない（同名ファイルがあれば手順 2 に戻る）。

### 5. 検証

`node scripts/news.mjs verify --slug <slug>` — 記事の検査、`astro check`、`astro build`、プレビュー表示を確認する。
失敗したら原因を直して再実行する。直し方が分からない場合は、エラー内容を分かりやすく説明して相談する。

### 6. 内容の確認と PR 作成

1. 編集者に記事の要点（タイトル、公開日、カテゴリー、下書きかどうか、画像の使い方、英訳で確認してほしい点）と
   プレビュー URL を示す。
2. `node scripts/news.mjs pr --slug <slug> --summary "<変更内容>" --translated --dry-run`（英訳がない場合は `--translated` を外す）
   を実行し、**リポジトリ・ブランチ・PR の作成/更新・ラベル・コミット作成者・コミットするファイル**を編集者に提示する。
   コミット作成者のメールアドレスが確認できなかった警告があれば、本人のものか確認する。
3. 編集者が了承したら、`--dry-run` を外して実行する（Push と PR 作成を行う、この Skill で唯一の外部操作）。

### 7. 報告

```
入稿 PR を作成しました 📝

- PR: <PR_URL>
- プレビュー（日本語）: <PREVIEW_JA>
- プレビュー（英語）: <PREVIEW_EN>
- 状態: 下書き（マージしても公開されません）

レビューで確認してほしい点: <英訳の確認点など>
修正したいときは「この記事の〇〇を直して」と伝えてください（同じ PR を更新します）。
```

PR 作成後はブランチを切り替えない（プレビューは PR と同じ内容を表示している）。

## 守ること

- **マージ・公開はしない。** `gh pr merge` やマージ操作は行わない。
- **`main` へ直接 Push しない。** Push は `news.mjs pr` 経由のみ。
- **破壊的な Git 操作をしない。** `git reset --hard`、`git push --force`、`git checkout -- <file>`、`git clean`、`git stash`、
  ブランチ削除などは実行しない。
- **記事と画像以外のファイルを変更しない。** 必要に見えた場合は作業を止めて編集者に報告する。
- **認証情報・機密情報を扱わない。** 原稿にパスワード・トークン・個人の連絡先など公開すべきでない情報があれば、指摘して確認する。
- `news.mjs` が ❌ で止まった場合、内容を編集者に分かりやすく伝え、勝手に回避策（別コマンドでの代替実行）をとらない。
- 環境の問題（Docker 停止、GitHub 未ログインなど）は `/setup-editor` を案内する。
